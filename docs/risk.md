# 封号风险与安全边界

## 官方规则怎么说

《微信个人账号使用规范》明确禁止对微信软件运行过程中的数据进行复制、修改、挂接运行，或使用**插件、外挂、非腾讯授权的第三方工具/服务**接入微信软件和相关系统。腾讯可以按情节采取警告、限制或禁止部分/全部功能、封禁账号直至注销等措施。

原文入口：[微信软件许可及服务协议](https://weixin.qq.com/agreement)、[微信个人账号使用规范](https://weixin.qq.com/agreement?lang=zh_CN&t=page/agreement/personal_account)。

这意味着：**只要不是微信官方开放的能力，自动化代回好友消息就存在账号风险。** UI 自动化只是降低了“技术特征”风险，并没有改变“未经授权自动化”的性质。

## 风险矩阵

| 方案 | 规则位置 | 技术检测面 | 相对风险 | 说明 |
| --- | --- | --- | --- | --- |
| 公众号 / 企业微信客服 API | 官方开放能力 | 无 | 低 | 合规首选；不能代回个人好友 |
| 微信 ClawBot 官方插件 | 官方插件通道 | 无 | 低 | 只能和机器人联系人对话 |
| macOS Accessibility + 键盘事件 | 未经授权自动化 | 中 | 中高 | 不注入，但行为仍是自动化 |
| Windows UI Automation / OCR | 未经授权自动化 | 中 | 中高 | 依赖窗口；群发/高频风险更高 |
| Android 无障碍服务 | 未经授权自动化 | 中高 | 高 | 无障碍权限本身容易被平台关注 |
| Hook / DLL 注入 / 改客户端 | 明确的外挂/非官方客户端 | 高 | 很高 | 还可能带来恶意代码和数据风险 |
| 模拟客户端协议 / Web 协议 | 非官方方式登录 | 高 | 很高 | 新账号通常无法登录 Web 微信 |

## 为什么“零封号风险”不可信

一些项目在 README 里写“100% 外部感知、零封号风险”。这只能说明它**不注入进程**，不能说明腾讯不会识别自动化行为。腾讯的处罚依据包括账号行为、频率、投诉、设备环境和平台规则，第三方工具无法承诺结果。

同样，“扫码登录”也不等于官方授权；“用了 AI”也不是处罚与否的关键，关键是接入方式和行为模式。

## 建议的安全边界

如果一定要在个人微信上试验，至少做到：

- **只用小号测试**，不要把主号、工作号、客户号作为第一个试验对象。
- **只开白名单私聊**，默认不碰群聊、公众号、服务号、陌生人和营销场景。
- **低频**：每小时/每天硬上限，随机延迟，随机跳过，不做“每句必回”。
- **限定时段**：夜间、开会、开车等场景不自动回复。
- **不做群发、加好友、拉群、营销、刷屏**；这些是风控重点。
- **提供退出机制**：对方说“人工/别自动回复/不要机器人”时立即停止该会话。
- **发送前二次校验**聊天名，避免切窗导致串发。
- **保留审计日志和总开关**；发现异常立即停用。
- **不要 24 小时挂机**，不要让自动化成为账号的主要行为。
- **不要购买“解封/防封”服务**，这类服务本身风险很高。

## 如果真的被限制

1. 立即停止所有自动化，退出第三方工具。
2. 查看微信里的具体提示：限制原因、范围、期限、申诉入口。
3. 按微信官方指引申诉，不要相信“内部解封”。
4. 不要继续用同一方式测试其他账号；先评估是否改用官方客服通道。

## 隐私与合规

- 聊天内容可能被发送到第三方大模型 API。需要确认对方知情，或至少不要在自动回复范围内处理敏感信息。
- 默认不要记录消息正文；只记录事件、联系人、耗时和错误。
- 涉及客户、订单、健康、金融等信息时，优先使用企业微信/公众号官方通道，并做数据最小化和权限隔离。
- 不要用自动回复冒充真人进行欺诈、诱导、营销或规避平台审核。
