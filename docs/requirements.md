# 落地前需要确认的信息

下面这些信息会直接决定技术路线和产品形态。标“默认”的是本项目当前采用的保守值。

## 1. 运行平台

| 选项 | 说明 |
| --- | --- |
| macOS（当前机器） | 已安装微信 4.1.15；Accessibility 方案可做，但项目少、需要自己维护 |
| Windows PC | 生态最成熟；`pywechat` / `easyChat` 可参考，但需要 Windows 机器 |
| Android 手机 | 无障碍/通知方案；手机需常驻，风险和维护成本高 |
| 服务器 | 只能做官方公众号/企业微信通道；不能直接跑桌面微信自动化 |

**默认**：macOS 本机，先做单聊天 MVP。

## 2. 使用场景

- 只回复指定好友的私聊？
- 需要回复群聊/群 @？
- 是客服接待、个人助理，还是“帮我应付消息”？
- 是否需要图片、语音、文件、引用、表情？
- 是否需要多账号？

**默认**：只处理白名单私聊文本；群聊、图片、语音、文件先不做。

## 3. 回复策略

| 模式 | 行为 | 风险/体验 |
| --- | --- | --- |
| `draft` | 只生成草稿，人工确认后发送 | 最安全，但需要人盯着 |
| `auto` | 白名单内自动发送 | 体验最好，风险最高 |
| `keyword` | 命中关键词才回复 | 可控，但不够自然 |

还需要确认：

- 活跃时段（默认 09:00–23:00）
- 回复延迟范围（默认 4–12 秒）
- 跳过概率（默认 15%）
- 每小时/每天上限（默认 8 / 40）
- 最长回复字数（默认 80 字）
- 哪些话必须转人工（默认包含“人工/别自动回复/不要机器人”等）

## 4. 模型与密钥

- 用哪家模型：DeepSeek / Qwen / Kimi / OpenAI / 本地 Ollama？
- API Base URL、模型名、Key 放在哪里？
- 是否允许把聊天内容发给云端模型？
- 是否有内容安全/敏感词要求？

**默认**：OpenAI 兼容接口，`DEEPSEEK_API_KEY` 环境变量，`deepseek-chat`。

## 5. 人设与边界

- 你的说话风格是什么？正式/随意/简短/幽默？
- 对不同联系人是否要有不同人设？
- 哪些话题不能聊（价格、承诺、隐私、政治、医疗、法律）？
- 不确定时是“说晚点确认”，还是“转人工”？

**默认**：自然、简短、像真人；不编造事实；不确定就说晚点确认。

## 6. 账号与风险承受

- 用主号还是小号？
- 能否接受“可能被警告/限制/封号”？
- 是否愿意先跑一周 `dry_run` 观察草稿质量？
- 出问题时的止损方式：关进程、拔网线、退出微信？

**默认**：小号、白名单、先 dry-run；不承诺任何账号安全。

## 7. 通知与人工接管

- 需要转人工时通知谁？飞书、邮件、macOS 通知？
- 是否需要审批队列：AI 生成草稿，人在手机/网页上点“发送”？
- 是否需要每日汇总：回复数量、跳过数量、失败原因？

**默认**：先本地日志；后续可接飞书机器人。

## 8. 交付形态

- 命令行脚本（当前）
- macOS 菜单栏 App
- 带审批界面的桌面 App
- 服务端 + 官方客服通道

**默认**：CLI MVP → 菜单栏 App → 可选审批队列。

## 最小启动信息

如果现在就要继续开发，至少给我这 5 项：

1. 平台：macOS 本机 / Windows / Android / 官方客服。
2. 场景：只回私聊 / 群聊也要 / 企业客服。
3. 模式：dry-run / 人工审批 / 全自动。
4. 模型：哪家、是否已有 API Key。
5. 账号：主号还是小号，能否接受封号风险。

其余项可以先用保守默认值。
